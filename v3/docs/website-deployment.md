# Website 部署与 AI 接口分工

你只负责 website，也可以负责部署它。当前前端是 React/Vite；后端是 FastAPI，另有本地数据库、录像和 RTX 3050 上的 AI 进程。网页上线与 AI 服务上线是两项交付。

## 当前代码能否直接上传

前端可以构建为静态文件，但目前不是独立展示网站：登录、数据加载、搜索、上传和视频播放都调用 `/api`。开发时 Vite 把它代理到本机 `http://127.0.0.1:8766`，这个开发代理不会随静态构建上线。当前也没有独立的静态演示模式。

因此只上传 frontend，可以托管页面资源，但完整登录和使用仍要后端配合。不要把 localhost 或 127.0.0.1 填成公网 API 地址。

## 推荐分工

| 负责 website 的人 | 负责后端/AI 的人 |
|---|---|
| 前端构建、Vercel 部署、域名、页面与交互 | 公网 HTTPS API、数据库、录像存储、AI 运行环境 |
| 连接 API、处理等待/错误/无结果状态 | API 格式、登录方式、权限、任务进度和失败响应 |
| 浏览器和手机联调验收 | 服务可用性、GPU/模型、处理速度和后台任务 |

当前本地整套程序依赖 RTX 3050、持久数据和后台进程，不能仅随 Vite 静态网页一起托管。AI 同学可以保留本机演示、另行准备服务端，或由团队选择合适的长期运行环境。网站部署不会自动把本机显卡变成线上推理服务。

## 路线 A：连接真实后端

1. 向后端同学取得稳定的 HTTPS API 地址、接口说明、演示账号和认证方式。当前接口约定见 `api-contract.md`，还要确认其线上实现与本前端是否一致。
2. 将要部署的源码放入团队可用的 Git 仓库。若仓库以 v3 为根，前端目录为 frontend；如果只把 frontend 建为独立仓库，项目根就是该仓库根目录。不要上传 .env、会话数据库、私有录像、虚拟环境、node_modules 或备份。
3. Vercel 新建项目并导入该仓库，设置：

   | 设置 | 仓库以 v3 为根时的值 |
   |---|---|
   | Framework Preset | Vite |
   | Root Directory | frontend |
   | Build Command | npm run build |
   | Output Directory | dist |

4. 为 `/api/*` 配置到真实 HTTPS 后端的反向代理，保留当前前端的同源访问方式；为其他页面配置 SPA 回退，确保 `/resident` 可直接打开。代理配置中的目标路径要与后端一致，例如后端接口实际是 `/api/search` 时，不要漏掉或重复 `/api`。此文档没有创建指向未知服务器的配置。
5. 后端需要允许实际网页域名。当前后端只允许本机 Origin；即使做了代理，登录等写请求也可能因 Origin 检查被拒。需同时检查 Cookie 的 HTTPS 设置、会话、实时更新、上传和视频范围播放；不能只修改 CORS 后就假定完成。
6. 先部署预览版，从另一台设备验证：登录 → 数据加载 → 搜索 → 回放 → 提交/更新 → 退出。AI 搜索必须确认确实连接了线上 AI，而非静态数据。

## 路线 B：独立 website 展示

如果后端同学暂时没有公网 API，可以另外实现明确标注的展示模式：使用可分享的演示数据、预先生成的搜索样例及已授权的视频；关键流程可交互，服务端写入和实时分析入口明确限制或禁用。这个模式可单独部署到 Vercel，不依赖现场 GPU 服务。

当前项目还没有这个模式，需要实现后才能形成可用的独立展示链接。它能证明 website 设计和交互；真实 AI 能力应由团队的实际运行视频/测试另行证明。不得把固定样例包装成在线实时 AI。

## 10 月 23 日交付建议

后端能按时提供线上 API，就选择路线 A；否则先完成路线 B 并标明展示范围，配团队的 5 分钟真实演示视频。你在团队材料中写清自己负责 website、前端部署和接口联调即可，不必把其他成员的模型工作写为自己的成果。
