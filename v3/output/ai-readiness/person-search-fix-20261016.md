# JagaAI 人物搜索误匹配修复

2026-10-16 · NVIDIA RTX 3050 Laptop GPU · 本地演示环境

已修复这次发现的“无人画面被当作人物命中”：`a person wearing a red jacket beside a white SUV` 现在只返回停车活动录像的 47 秒、30 秒画面，之前额外返回的机械停车场 90 秒画面已排除。搜索阈值仍为 0.65。

## 修复方式

模型的自然语言说明不再独立证明画面里有人。每个抽样瞬间先用 YOLOX-S 检测人体，再放大对应区域重新检测；两步通过的人体框、时间和关键帧名称一起保存。人物查询只使用同一抽样画面上复核通过的说明，正式结果和相近片段都执行此限制。人数变化带来的补采样仍保留；周期采样落在跳过检测的帧时，会补做该帧检测，避免挪用上一帧的人体框。

全部 51 个已有抽样画面已用原录像的对应帧补检，其中 33 帧有通过复核的人体框、18 帧未通过。后者是检测结论，不是独立人工的“确定无人”标注。旧说明与向量保留供追溯；它们不能绕过人物门槛。缺少或错位的旧依据不会作为人物结果，覆盖率会提示需要重新分析。

停车场机械录像在 117 秒以后确实出现行人，这些通过复核的画面仍可检索；没有整段屏蔽录像或针对某句话设置黑名单。

## 验证

| 检查 | 实测结果 |
|---|---|
| 13 种红衣白车 / 黑衣楼梯问法 | 英、中、马来文均找到预期有人录像 |
| 5 种不存在的紫衣 / 大象条件 | 无明确命中 |
| 2 个无人时段 × 4 种人物问法 | 正式结果、相近片段均为空；显示已分析 1/1 |
| 3 种越线查询 | 各返回原有 3 个事件 |
| 打架查询 | 明确提示不支持 |
| 上述 30 项按正序、倒序、正序重复 | 90/90 通过，耗时中位数 0.604 秒 |
| 重新分析有人 / 无人录像，再跑完整 30 项 | 30/30 通过，耗时中位数 0.611 秒 |
| 7 段录像的范围播放请求 | 全部通过 |
| 页面搜索、点击、实际播放 | 定位至停车录像 00:47，正常播放至 00:50 |
| Python 自动检查 | 105 通过；1 条第三方测试客户端弃用提示 |
| 原业务数据库 | 与本次修改前备份的数据转储哈希一致，完整性正常 |

人物查询回归同时检查每个展示结果的检测支持标记、所有命中是否来自预期录像，以及已知 90 秒无人画面没有混入正式或相近结果。自动检查另覆盖高相似度的虚构人物说明、旧索引、时间/关键帧错位、机械候选无法通过裁剪检查，以及过期/重跑期间不得披露旧数据。

GPU 实际执行记录使用 `CUDAExecutionProvider`；启动器仍按 RTX 3050 UUID 选择设备，AMD ROCm/Vulkan 关闭。原业务数据与演示数据分开保存。

重新分析的楼梯有人片段用时 73.478 秒：0 秒无人体依据，5.6 秒和 7.4 秒通过人体复核；空楼梯片段用时 45.710 秒，0 秒抽样没有人体依据。两段都正常完成说明和向量生成，没有错误。最终数据库仍有 51 个抽样说明，全部带有时间、关键帧一致的检查依据；越线事件仍为 3 个。

这是现有公开素材和上述问法的演示稳定性检查。小目标、遮挡可能被严格门槛漏掉，检测器仍可能误判；颜色、人物与车辆的关系也仍需人工核对。此结果不能作为所有录像均零误报或真实安防部署准确率的证明。R1 真实停留正例和夜间效果仍未验证。
