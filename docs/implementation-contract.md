# Local implementation contract

All runtime services bind to 127.0.0.1. No Firebase, remote repository, deployment, cloud AI or telemetry. npm install may download dependencies. Uploaded files never leave the machine. English UI, UTC storage, Asia/Kuala_Lumpur display. Reports, alerts and incidents separate. Seeded items/fixtures clearly labelled synthetic demo data.

## Shared store (root owns packages/shared/store.ts)
SQLite documents with id, kind, townshipId, JSON data. Export `dataDir`, `mediaDir`, `db`, `uid(prefix)`, `now()`, `get<T=any>(kind,id)`, `list<T=any>(kind,townshipId?)`, `put(kind, record)` (upsert), `remove(kind,id)`, `transaction(fn)`. Record must have id and townshipId unless global. Synchronous transactions: callback cannot await. Each process has own SQLite connection, WAL and busy timeout. IDs globally unique. `get/list` return parsed records, undefined if missing. `audit(actor, action, targetType, targetId)` writes auditLogs record. API owns seed.ts and auth.ts. Shared model types optional.

## API contract (API agent owns apps/api/src)
All paths `/api`. JSON return directly objects/arrays (no envelope), errors `{error:string}`. Authentication opaque HttpOnly cookie `jagaai_session`, browser credentials same origin. `POST /auth/login {email,password}` -> user. `POST /auth/logout`, `GET /me` -> user `{id,name,email,role,townshipId,membershipStatus}`. Demo password `JagaLocal!2026`, emails `manager@jaga.local`, `guard@jaga.local`, `resident@jaga.local`. Additional other-township user for security tests. Disabled user rejected on every request.

`GET /bootstrap` -> `{user,locations,members,reports,incidents,assignments,activities,registrations,pointTransactions,videos,jobs,alerts,segments,capabilities}` filtered by role; management gets all township objects; resident only own reports/incidents limited public progress and personal points, no media CCTV; guard only assigned incidents/reports/evidence. `capabilities` describes local/demo and AI mode. Management members list excludes password hash. Location `{id,name,zone}`. Names seed: North Gate, Lakeside Walk, Clubhouse, Block A.

`GET /reports`, `GET /reports/:id`, `POST /reports` multipart (fields category,locationId,timeFrom,timeTo,description; up to 3 photos field `photos`) -> report `{id,number,reporterId,locationId,category,timeFrom,timeTo,description,photoIds,status,incidentId?,publicUpdates:[],createdAt}`. `POST /reports/:id/link {incidentId}` management. `POST /reports/:id/review {status:reviewing|resolved|rejected,reason}` management.

`GET /incidents`, `GET /incidents/:id` -> record plus updates/evidence; `POST /incidents {title,category,locationId,priority,reportId?,alertId?}` -> `{id,title,category,locationId,priority,status,createdBy,createdAt}`. `POST /incidents/:id/assignments {assigneeId}` -> assignment. `POST /incidents/:id/updates {action:accept|arrive|resolve|close|reopen|note,note,visibility:public|internal}` -> incident. API validates state transitions; guard must own active assignment; only manager closes/reopens; close/reopen require note. Reports linked sync public progress. Assignment `{id,incidentId,assigneeId,status,acceptedAt?,arrivedAt?,result?}`. Incident updates kind `incidentUpdates`, `{id,incidentId,authorId,action,note,visibility,createdAt}`.

`GET /activities`; `POST /activities {title,type,locationId,startAt,endAt,capacity,points,description}` -> published record; `POST /activities/:id/cancel {reason}`; `POST /activities/:id/register`; `DELETE /activities/:id/registration`; `POST /activities/:id/attendance {userId}` management -> `{registration,transaction,alreadyAwarded}`. Transactions capacity+unique; attendance requires end/start eligibility? allow once activity has started, forbid future event awards. Demo seed past activity registered resident (verifiable) and future activities. `GET /me/points` -> array. `PATCH /members/:id {membershipStatus,role?}` management prevent disabling last active manager/self last manager. Roles management, guard,resident.

`GET /cameras`; `POST /cameras {name,locationId}`. `POST /videos` multipart `file` MP4, cameraId,recordedAt -> video `{id,cameraId,locationId,mediaId,recordedAt,durationSec,status,expiresAt,createdAt,source:upload|synthetic_fixture}`. Validate real format probe. `POST /videos/:id/analyze` -> job; unique active/completed analysisVersion `local-v1`; retry failed only, attempt max 3; `GET /videos/:id`; `GET /jobs/:id`. `POST /video-search {query,locationId?,timeFrom?,timeTo?,confirmRelativeDate?}` -> `{results:[{...segment,score,matchReason,video}],coverage:{unanalysedVideos:number},notice,parsed?}`. Keywords/structured local ranking; relative terms trigger needsConfirmation and parsed times, do not silently guess. `GET /alerts`; `POST /alerts/:id/review {decision:confirm|dismiss|link,reason?,incidentId?}`. Confirm creates incident or links provided existing id; dismiss needs reason. `GET /audit`.

`GET /media/:id/access` -> `{url:'/api/media/:id/content?ticket=...',expiresAt}` audited; opaque short lived ticket bound to active session, role and object authorization revalidated on content; no static media route. Support video Range requests. Resident only own report photos; guard task evidence. Media record `{id,townshipId,path,contentType,kind:video|photo|thumbnail,ownerId?,reportId?,videoId?,expiresAt?}`.

## Worker contract (worker agent owns apps/worker/src and scripts/create-fixtures.ts)
Kinds videos, analysisJobs, segments, alerts, media. Job `{id,townshipId,videoId,status,attemptCount,leaseUntil?,leaseOwner?,lastError?,nextAttemptAt?,createdAt,updatedAt,analysisVersion:'local-v1'}`. Video queued/uploaded/processing/completed/failed/expired. Segment `{id,townshipId,videoId,cameraId,locationId,startSec,endSec,absoluteStartAt,summary,observations:[{startSec,endSec,description}],analysisVersion,analysisMode:'fixture'|'ollama',model,promptVersion}`; all timestamp in original video seconds. Alert `{id,townshipId,videoId,cameraId,locationId,segmentIds,eventType:'possible_fall'|'prolonged_lying',startSec,endSec,evidence,uncertainties,reviewStatus:'pending_review',createdAt,analysisMode}`. Worker segments 15s overlap3, heartbeat, transactional claim+lease, max3 backoff. Strict validation, idempotency across restarts. Fixture only for approved built-in synthetic files, never invented analysis for arbitrary upload. Unknown upload in fixture mode fails actionable "Local vision model required". Ollama mode only loopback URL; extract frames local + JSON schema; no outbound runtime. Export probe/validation helpers if needed. FFmpeg dependencies ffmpeg-static and ffprobe-static.

Fixtures generator writes media+videos+fixture manifest under data/fixtures and synthetic MP4 (clearly captioned), built-in analysis keyed by exact file hash, not name. Create ~3 short demo videos walking/possible fall/bicycle movement, seed camera mapping. Generator can enqueue analysis jobs. Root `scripts/dev.mjs` starts api/worker/vite; fixture command separate. Retention removes files, segments, thumbnails, alerts or marks media unavailable; no cloud copies.
